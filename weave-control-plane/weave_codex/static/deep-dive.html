A SOURCE-LEVEL ANATOMY · AUGUST 2026

Codex is already
a harness.

It is not a chatbot with a shell bolted on. It is a stateful agent runtime that assembles context, samples a model, executes typed tools, mediates permissions, compacts history, and keeps going until a turn reaches a terminal state.

Audited version 9ded177
Public boundary Codex app-server
Reading time 16 minutes
WEAVE DIFF 01

Weave does not replace that harness. It adds a human-authored program around it: goal-level phases, explicit checkpoints, selected experience, verification, and a receipt tying intent to the underlying Codex trace.

The most important fact is also the easiest to miss: one Codex turn is a loop. “Build Flappy Bird” may trigger a hundred reads, commands, edits, image inspections, and browser checks. Those events are the inside of the instruction. Treating every event as a workflow block would make a capable agent brittle—and give the user a canvas they could not reasonably author.

01

THE WHOLE SYSTEM

A client around a runtime around a loop

Codex exposes a deep integration surface through app-server. A client initializes one connection, starts or resumes a thread, starts a turn, answers server-originated approval requests, and consumes streamed notifications. Inside, core captures the current world, prepares the model-visible history, and routes any requested actions through the tool runtime.

OpenAI identifies it as the interface for rich integrations needing authentication, history, approvals, and streamed events.

IMPLEMENTED BY WEAVE

A control plane, not a replacement

Today Weave compiles a small ordered phase program, keeps one Codex thread, and saves a privacy-reduced projection beside the receipt.

WEAVE INTEGRATION

Your Codex subscription stays with Codex

Weave asks app-server for account state and uses its managed ChatGPT browser-login flow. It never reads, copies, or serves Codex's local credential file or tokens.

02

THE ACTUAL UNIT OF AGENCY

A turn is not a model call

The central run_turn path repeatedly captures state, normalizes history, samples the model, executes requested tools, records their outputs, and samples again. New steering input can enter between samples. A stop hook can request continuation even after the model appears finished.

THE ABSTRACTION TEST

Wrong authoring unit Read → Edit → Test

A guessed sequence of individual tool calls.

Correct authoring unit “Build the playable game”

A goal with context, policy, evidence, and a completion contract.

WHAT THE MODEL SEES

Context is constructed, not replayed

“Chat history” is too weak a description. Codex maintains append-ordered Responses items, normalizes call/output pairs, truncates tool output at a boundary, and combines that history with typed world-state sections. Model instructions, AGENTS.md, permissions, environment, extensions, skills, plugins, and deferred tools all participate.

World state uses baselines

On the first normal turn, Codex injects a full snapshot. Later steps may contribute only changes relative to a stable baseline. A history rewrite invalidates that baseline and triggers full reinjection.

World-state source ↗

Compaction transforms the prompt

Compaction creates replacement model-visible history while preserving a record of the boundary. It does not erase the earlier trace, and the resulting prompt is not a byte-for-byte replay.

WEAVE DIFF 02 · CONTEXT

What is actually added

The current runner can inject excerpts from explicitly selected prior threads into the first work phase. It records which thread IDs were selected and does not repeatedly paste the same excerpts into later phases. This is not a native “attach these traces” Codex field, and it is not yet a retrieval graph.

04

TOOLS, CONSENT, CONTAINMENT

Approval and sandboxing are different

A model-requested action is routed through a registry, hooks, approval logic, and a selected sandbox. “May the user allow this?” and “what can the process access?” are separate questions. A sandbox denial may be returned to the model as ordinary evidence, allowing another tactic, or may trigger an approved escalated retry.

WEAVE DIFF 03 · CONTROL

Two human control points, not one

Codex-native approvals still govern risky actions inside a work phase. A Weave checkpoint pauses between phases without calling the model—for example, approve a plan before any implementation phase starts. Both decisions are captured in the run receipt.

05

OBSERVABILITY WITHOUT FICTION

There is no single “complete trace”

Codex emits a responsive live stream, stores a selected durable rollout for continuation, and can optionally produce a sensitive local diagnostic trace. These records serve different purposes. None exposes hidden chain of thought, and ordinary thread history is not a byte-perfect reconstruction of every transient event.

LIVE

App-server stream

Item lifecycle, text and command deltas, approvals, transient errors, turn status.

Best for responsive UI
DURABLE

Thread + rollout

Selected semantic history used for persistence, reading, resuming, and forking.

Best for continuation

Raw local trace

Optional, internal, sensitive diagnostic events. Not a stable public API.

NOW REVEAL THE CONTROL PLANE

What Weave changes—and what it leaves alone

Codex answers: How should I accomplish this goal? Weave answers the question one level above it: Which goals should run, under what boundaries, with which human decisions, and what evidence must survive afterward?

SHIPS IN THIS PROTOTYPEOrdered programs of ≤ 8 phases
  • work: exactly one Codex turn; internally unbounded
  • checkpoint: local human continue/stop; no model call
  • verify: one structured turn plus 0–2 declared repair turns

Not claimed: arbitrary branches, per-phase forks, deterministic artifact gates, strict per-phase first-party tool allowlists, a retrieval graph, or hard limits on model/tool iterations inside a turn. A derived trace projection is labeled derived; it is not presented as Codex's hidden plan.

“Design a polished Flappy Bird game.”

REGULAR CODEX

You state the goal once. Codex decides how to inspect the repository, implement the game, run it, inspect the result, and iterate.

EXAMPLE 02 · HIGH-RISK REPOSITORY CHANGE

“Replace session auth without breaking existing clients.”

REGULAR CODEX

Codex can investigate and implement the migration in one task, asking for protected-action approval when required.

One adaptive tasktrace callers · change schema · migrate · test · answerAction safety is mediated, but the architecture decision and migration gate are implicit.

WEAVE + CODEX

  1. WORK
    Map auth contracts and blast radiusNo edits. Produce callers, invariants, and migration risks.
  2. HUMAN
    Accept the migration contractA person owns the compatibility decision.
  3. WORK
    Implement the accepted migrationWorkspace-write; native Codex approvals still apply inside.
  4. VERIFY
    Prove old and new clientsStructured verification; up to two bounded repair turns.
The advantage is governance with evidence. The risky choice becomes a named boundary rather than an inference buried inside a long trace.

THE PRODUCT THESIS

Let Codex choose the tactics.
Let people own the system.

Open source gives us the rare opportunity to build against a real, inspectable agent runtime. The useful innovation is not a prettier tool-call graph. It is a truthful control plane that makes intent, boundaries, experience, human judgment, and evidence first-class—while leaving Codex free to be adaptive inside each goal.
